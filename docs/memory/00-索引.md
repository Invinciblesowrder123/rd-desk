## 三条贯穿全局的原则

写在这里，因为后面每个决策都是它的推论：

**一、只有一个数据真身。**
中途出现过"页面推快照、服务端存镜像"的过渡形态，两个浏览器同时用会互相覆盖。
现在数据结构是 `bridge/desk.db` 一份，所有端要么读它，要么读写它。

**二、改数据只留一个入口。**
飞书机器人接进来时，一开始想让它也能报进度。放弃了——两个写入口必然分叉，
最后一个说话的人赢，没人知道哪份对。现在 bot 只读。

**三、宁可承认做不到，也不要看起来在跑。**
所有"降级/兜底"都被显式去掉：读不到数据就报错，不显示上一次的内容冒充新的；
没配模型就直说，不用本地模板拼答案。
