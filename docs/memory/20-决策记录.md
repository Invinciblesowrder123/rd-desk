# 决策记录

格式：编号 / 决策 / 为什么 / 代价。**代价那一列是重点**——没有代价的决策通常是没想清楚。

---

## D1 · 本仓库是唯一数据真身，其余系统只读

- **决策**：`bridge/desk.db` 是唯一事实来源；飞书机器人、任何导出、任何旧备份都不得反向覆盖它。
- **为什么**：曾经存在"云端一份、本地一份、bot 一份"的三份数据，谁都不准，
  问同一个问题能得到三个答案。选一个真身是唯一解法。
- **代价**：所有依赖方都要改（bot 改成只读、云端整套下线）。
- **影响**：`local/server.py`、`integration/pmbot/zhongtai.py`

---

## D2 · 项目不拆成更细的节点

- **决策**：一个项目几个节点就几个节点，不为了图表好看去硬拆。
- **为什么**：节点是给人干活的，不是给系统算数的。硬拆出来的节点没人认，
  到期不会有人去做，反而污染逾期统计。
- **代价**：只有一个节点的项目，进度条只有 0% 和 100% 两档；节点一完成，
  项目看起来就"完成"了（曾出现过 1/1 显示 100% 但项目还在跑的情况）。
- **状态**：已确认接受，不视为 bug。

---

## D3 · 节点延期完成不留痕

- **决策**：不记录"计划 10-21、实际 10-29、晚 8 天"这类偏差。
- **为什么**：当前目的是推进，不是考核。留痕会让报工变成"填表"，
  人会开始修饰日期，数据反而更假。
- **代价**：答不了"这个月节点准时率"这种问题。真要看，得从别的系统补。

---

## D4 · 字段不许借用语义

- **决策**：「阻塞项」只放真的卡住、需要决策的事；「逾期」由系统按计划完成日自己算。
- **为什么**：早期把"逾期 2 天""临期 1 天"这类预警拼成人话塞进「阻塞项」，
  结果这一列读起来像"项目被什么卡住了"，实际只是没做完。字段语义一旦被污染，
  后面所有基于它的判断都会歪。
- **代价**：预警信息没有独立承载列，只能在页面按日期现算（成本极低，值得）。

---

## D5 · 下线云端那一套

- **决策**：云端页面取消发布，四张表清空；代码里不再产出云端版本。
- **为什么**：使用环境到不了云端的域名，那套东西实际不可用，留着只会让人以为有两份数据。
- **代价**：失去了"多端访问"和"云端备份"。补偿手段是导出 JSON / 拷 db 文件。
- **注意**：云端页面节点本身删不掉（平台没有删除接口），只能取消发布 + 清空数据。

---

## D6 · 服务端库成为真身（页面不再自己存数据）

- **决策**：数据存服务端 SQLite，页面通过 `/api` 读写。
- **为什么**：让页面自己存（localStorage）会导致"多端互相覆盖"，且 Python 侧读不到数据。
  详见 [10-架构演进.md](10-架构演进.md) 阶段 2 的实测。
- **代价**：**失去离线能力**（服务不跑页面是空的）；每次操作多一次本地 HTTP 往返。
- **补偿**：保留 `legacy.html`（纯 localStorage + 内置快照），应急可看。

---

## D7 · 飞书机器人只读

- **决策**：bot 能查不能改，8 个写工具一律返回"请到中台操作"。
- **为什么**：两个写入口必然分叉。而且 bot 的写入绕过了页面的校验与联动
  （比如完成节点要同时写报工）。
- **代价**：在飞书里说"XX 完成了"不会有任何效果，得回页面点。
- **配套**：系统提示词和帮助文本都要改，否则模型会答应做不到的事。

---

## D8 · 项目名带客户前缀

- **决策**：`项目名 = "客户 项目名"`，单空格分隔（如 `星河 智能咖啡机`）。
- **为什么**：不同客户会有同名项目（同款产品的不同客户版本），光看名字分不清。
- **代价**：名字变长，窄屏卡片会折行；改名要连带改历史报工里的名称快照。

---

## D9 · 只绑本机，不做局域网共享

- **决策**：服务绑 `127.0.0.1`，不提供账号体系。
- **为什么**：`/api` 是无认证的写接口。一旦暴露到局域网，等于谁都能改数据。
  要么加鉴权，要么别开——目前选了后者。
- **代价**：同事看不到，只能投屏或导出。

---

## D10 · 整行存 JSON + 视图，而不是一列一字段

- **决策**：`records.data` 存整行 JSON，字段查询靠 SQLite 视图。
- **为什么**：字段是长期演进的（客户、负责人、节点状态都是后加的），
  JSON 存法加字段零迁移；数据量千级，性能不是瓶颈。
- **代价**：不能直接 `WHERE 某列`，要查视图；索引只能建在视图之外的物理列上。
