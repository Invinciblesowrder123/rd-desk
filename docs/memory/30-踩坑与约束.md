# 踩坑与约束

按"症状 → 原因 → 做法"记。都是实际撞到过的，不是猜的。

---

## 一、存储与数据

### 1. localStorage 不是数据库

**症状**：想写 SQL 查询、想 join、想让外部程序读数据，全都做不到。

**原因**：它是浏览器进程私有的字符串存储，没有表结构、没有索引、不能跨进程。
"同步数据库"这个说法在那种结构下根本不成立。

**做法**：要真数据库，就得让服务端持有数据（见 [20-决策记录.md](20-决策记录.md) D6）。

### 2. 全量替换 = 最后写者赢

**症状**：两个窗口同时用，一方保存后另一方的改动消失。

**原因**：同步实现成"推整份数据，服务端先 DELETE 再 INSERT"。

**做法**：改成按记录增删改；跨端靠 `rev` 轮询刷新，不再整份覆盖。

### 3. 只拷 `.db` 不拷 `-wal` 会丢数据

**症状**：备份出来的库比线上少几条记录。

**原因**：SQLite 开了 WAL，最近的写入还在 `-wal` 文件里没合并进主文件。

**做法**：备份前先停服务（会自动 checkpoint），或者把 `-wal`、`-shm` 一起拷。

### 4. 灌种子只发生一次

**症状**：换了 `data/seed.json`，重启后数据没变。

**原因**：建种子只在库为空时执行。

**做法**：删掉 `bridge/desk.db` 再启动。

## 二、进程与启停

### 5. 不要按进程名杀进程

**症状**：一停服务，机器上别的 python 也死了。

**原因**：`taskkill /IM python.exe` 是无差别攻击。

**做法**：按**命令行特征**匹配（`server.py 8787`、`run_pmbot.py feishu-ws --env .env.prod`）。
先 `--dry-run` 看会杀谁，再动手。

### 6. `powershell` 不在 PATH 里

**症状**：Python 里 `subprocess.run(["powershell", ...])` 抛 `FileNotFoundError`。

**原因**：PATH 只包含 `System32` 的一部分，PowerShell 目录没进去。

**做法**：用完整路径 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`。
顺带一提：某些环境下 `wmic` 会被安全策略拉黑，别依赖它。

### 7. 后台进程随启动它的进程一起死

**症状**：脚本里 spawn 出去的进程，脚本一退出就没了。

**原因**：Windows 的 Job 对象在会话结束时清理子进程树，`DETACHED_PROCESS` 也可能逃不掉。

**做法**：正常双击 `.bat` 启动不受影响；自动化脚本里验证时要留意这个假象。
（本次开发中几次"启动后秒死"就是这个，不是代码问题。）

## 三、网络与代理

### 8. 探测本机端口走了代理

**症状**：`curl http://127.0.0.1:8787/api/rev` 返回 502；Python 里健康检查永远失败。

**原因**：环境变量 `HTTP_PROXY` / `HTTPS_PROXY` 被设成了公司代理，
urllib 和 curl 默认会用它，localhost 也不例外。

**做法**：`curl --noproxy '*'`；Python 用
`urllib.request.build_opener(urllib.request.ProxyHandler({}))`。

### 9. `file://` 下页面是空的

**症状**：双击 `index.html`，页面没有任何数据。

**原因**：`/api` 是相对路径，`file://` 没有源，请求直接失败；有的浏览器连 localStorage 也禁。

**做法**：必须通过 `http://127.0.0.1:8787/` 打开。

## 四、pmbot 相关

### 10. 系统 Python 缺 tzdata，import 就崩

**症状**：`import pmbot.agent` 抛 `ZoneInfoNotFoundError: 'No time zone found with key Asia/Shanghai'`。

**原因**：代码里用了 `ZoneInfo("Asia/Shanghai")`，而某些 Python 发行版不带时区库。

**做法**：用项目自带的运行时（`python-embed/python.exe`）跑，别用系统 Python。

### 11. pmbot 有多个库文件

**症状**：改了数据但 bot 看到的还是旧的。

**原因**：根目录、`runtime/prod`、`runtime/test` 各有一个 `pmbot.db`，内容不同。
`PMBOT_HOME` 决定用哪个。

**做法**：先确认 `PMBOT_HOME`，再动手；改配置时别只改 `.env` 忘了 `.env.prod`。

## 五、页面与渲染

### 12. 甘特图右下角文字叠影

**症状**：节点数超过 5 的项目，甘特图右下角的结束日期看上去"重影"。

**原因**：紧凑视图只画 5 行，多出来的用 `+N` 提示；`+N` 和结束日期用了同一个
右对齐锚点、基线只差 1 像素，两层字正好叠在一起。

**做法**：有溢出提示时底部多留一行，`+N` 提到日期上方单独一行。

### 13. 单节点项目的"假完成"

**症状**：某个项目显示完成率 100%，实际还在跑。

**原因**：它只有一个节点，且已完成。节点驱动进度的固有结果。

**做法**：不改逻辑（见 D2），用的时候心里有数：1 个节点的项目，进度条没有信息量。

### 14. 改源码不生效

**症状**：改了 `src/build/*.js`，页面没变化。

**做法**：`local/index.html` 是构建产物，要跑 `python src/build.py` 重新拼。

## 六、并发与版本

### 15. 两个写请求撞在一起，SQLite 报"只读"

**症状**：点"完成节点"偶发弹"操作失败"，但节点其实已经置完成了；服务日志里是
`OperationalError: attempt to write a readonly database`。数据没坏
（`PRAGMA integrity_check` 仍然 ok），只是写请求被拒。

**原因**：`完成节点` 是复合动作——节点置完成 + 记一条报工，前端一次发两个写请求。
服务端是 `ThreadingHTTPServer`，两个线程各开一条连接同时写；WAL 模式下**最后
一个连接关闭时会删掉 `-wal`/`-shm`**，两边正好撞上"刚删、同时重建"，其中一边就
降级成只读。更麻烦的是前端用 `Promise.all`，一个失败整体 reject，于是出现
"节点写成功、报工没写成"的半成功脏状态。

**做法**：三道防线，缺一不可——

1. `deskdb` 常驻一条 keeper 连接，`-wal`/`-shm` 一直在，不会被删，也就没有重建竞态；
2. 全局写锁 `_WRITE_LOCK` 把所有写操作串行化，同一时刻只有一个写者；
3. 复合动作改走 `POST /api/db/<id>/batch`，服务端在**一个事务**里做完，要么全成、
   要么全不成，前端不再自己拼两次请求。

另：进程退出前必须走 `close_keeper()`（`POST /api/shutdown` 会调），让它正常
checkpoint 并清理 `-wal`/`-shm`。**强杀进程会跳过 checkpoint，留下残留文件**，
下个进程恢复 WAL 时可能降级成只读——看到 `readonly database` 先查是不是被强杀过，
别急着动数据。

### 16. 服务在跑，页面还是旧的

**症状**：改了 `src/build/*.js`、重新构建、重启服务，浏览器里还是旧行为——
旧版错误提示关不掉、旧版并发写报错照旧。很容易误判成"改了没用"。

**原因**：页面 JS 只在打开时加载一次。服务端换了文件，已经开着的标签页不会重新
拉取；`/api/rev` 只变了版本号，页面照样用内存里那份旧脚本。

**做法**：`/api/rev` 额外返回 `build`（`index.html` 的 mtime），页面把它和自己
打开时的值比对，不一致就提示"页面有新版本，刷新后生效"。排查任何前端问题时，
第一个动作是 Ctrl+F5。
