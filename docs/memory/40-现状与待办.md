## 如果以后要往前走

按投入从小到大排，前三条是真正会碰到的：

1. **给「阻塞项」加个真正的用途**（现在多数项目是空的）。可以配合"阻塞要指定责任人和
   预计解除日"，不然这列会退化成备注。
2. **决策改为：要不要支持局域网多人用**。需要 HTTPS + 登录 + 操作审计，
   基本等于把 `server.py` 换成正经 web 服务，工作量不小。
3. **节点加业务主键**（比如继承外部系统的节点 id）。现在按名称对齐，
   改名会导致节点"删了又加"，历史报工的关联会断。
4. 阶段字段细化，或者干脆去掉——它现在既不能筛选也不能统计。
5. 把"预计完成日（ETA）"的算法显式化：目前按近 7 天完成节点数外推，
   对节点少的项目波动很大，界面上会显示"暂无推算"，容易被误读成功能坏了。
